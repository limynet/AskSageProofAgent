that:

## Step b. Build the prompt loader with hardcoded fallback

b.1 Create src\prompt_store.py:
  - class PromptStore: loads configs\prompts.json once at init; method
    get_prompt(stage_id, variant=None) -> dict with keys model, temperature,
    max_tokens, system_prompt, prompt_template, file_variables.
  - validate_variables(stage_id, render_kwargs): raises ValueError if a
    template placeholder in file_variables is missing from render_kwargs.
  - On missing file or missing stage key: fall back to
    src\prompts_fallback.py and log a warning.

    is no JSON config file, create configs\app_config.json with

    src\llm_client.py's outlet contract.

Gate: unit-test that PromptStore returns the exact s1 prompt text and falls

## Step c. Build the 7-stage engine module

c.1 Create src\seven_stage_engine.py with:
  - dataclass Finding: exactly the schema in G1-R2 section 5.
  - async or sync functions run_s1..run_s7(ctx, client), where ctx is a dict
    carrying the parsed document text, sections, and accumulated findings;
    client is LLMClient. Each run_sN renders the template via PromptStore,
    calls client.chat_completion(messages=[system?, user], model=...,
    temperature=..., max_tokens=...), parses the model output (JSON where
    the prompt requests JSON; else text stored raw), normalizes severity and
    domain per G1-R2 section 5, and appends Findings to ctx.
  - run_s6_dedup(ctx): deterministic only (dedupe findings by normalized
    (location.quote, issue) similarity; exact-match on lowercase stripped
    quote plus fuzzy prefix match is acceptable in G1).
  - run_all(ctx, client): s1..s7 in order, returning the final report string
    plus the findings list.
c.2 Create src\compliance.py: port the regex label logic from
    DAPAM_OCR\pubs_review\utils\compliance.py; emit Findings with
    source="regex" and the severity mapping from G1-R2 section 5. Copy the
    regexes verbatim; keep the file ASCII.
c.3 Wire into src\pipeline.py:
  - Keep all 7 existing stage names. When engine_mode == "seven_stage",
    the rules stage calls run_s1 + compliance + run_s2;
    agent_citation -> run_s3; agent_apa -> run_s4; agent_sme -> run_s5;
    summary -> run_s6 + run_s7 + render.
  - Keep engine_mode "legacy_chunked" routing to the existing
    src\review_agents.py path untouched.
c.4 Wire into src\runner.py so background runs use the same pipeline entry
    point (it already goes through pipeline.py; just confirm no direct
    review_agents import bypasses engine_mode, and fix if found).
c.5 UI: if app.py exposes engine_mode or stage labels, no label change is
    required (stage names unchanged). Only add a config-driven indicator if
    it is a one-line change; do not redesign the Dash layout in G1.

Gate: with a stub client, run_all completes end-to-end on synthetic text.
